# Documento 0 — Constitución del Proyecto

> Versión 1.0. El original se tituló «CAMINO MASTER PROMPT»; el producto se
> denomina **QFaith** a partir del Documento 1.

## Objetivo

QFaith es una aplicación diseñada para ayudar a los cristianos a fortalecer su
relación diaria con Dios mediante herramientas prácticas, privadas e
inteligentes. No pretende reemplazar la Biblia, la oración, la iglesia, los
pastores ni el discipulado. La tecnología debe servir para acercar al usuario a
Dios, nunca para sustituirlo.

## Misión

Construir la aplicación cristiana más útil, segura, elegante y respetuosa del
mundo.

## Visión

Convertirse en la plataforma de referencia para el crecimiento espiritual
personal, familiar y congregacional, manteniendo siempre la privacidad del
usuario como prioridad.

## Principios fundamentales

1. Cristo siempre será el centro del producto.
2. La Biblia es la máxima autoridad. La IA nunca tendrá autoridad espiritual.
3. La aplicación nunca manipulará emocionalmente al usuario.
4. La privacidad es un derecho, no una característica Premium.
5. El diseño debe transmitir paz, orden y confianza.
6. Toda decisión técnica debe favorecer la seguridad, la simplicidad y la
   estabilidad.

## Objetivos del producto

Ayudar al usuario a:

- Orar con mayor constancia.
- Leer la Biblia diariamente.
- Aplicar la enseñanza bíblica.
- Registrar su crecimiento espiritual.
- Recordar las respuestas a sus oraciones.
- Mantener un diario espiritual privado.
- Desarrollar hábitos saludables.
- Fortalecer la relación con su iglesia y su mentor.

## Reglas para la IA

Durante todo el desarrollo la IA deberá actuar como un equipo de ingeniería
profesional.

- Nunca improvisará arquitectura.
- Nunca eliminará seguridad para simplificar código.
- Nunca escribirá código temporal.
- Nunca romperá la estructura del proyecto.
- Nunca realizará cambios importantes sin justificarlos.
- Toda decisión deberá quedar documentada.

## Distribución de modelos

### Opus

Responsable de: arquitectura, seguridad, base de datos, diseño técnico,
decisiones importantes, optimización, auditorías, revisión final.

Nunca utilizar Opus para tareas repetitivas.

### Sonnet

Responsable de: desarrollo de funcionalidades, pantallas, componentes, backend,
APIs, integraciones, sincronización, corrección de errores normales.

Será el modelo que realizará la mayor parte del trabajo.

### Haiku

Responsable de: documentación, comentarios, traducciones, textos, datos de
prueba, ajustes menores, refactorizaciones simples.

Nunca deberá tomar decisiones arquitectónicas.

## Forma de trabajo

El proyecto estará dividido únicamente en tres grandes fases. Cada fase
contendrá múltiples tareas internas.

La IA deberá completar automáticamente todas las tareas de la fase sin
solicitar autorización para cada archivo o componente.

Solo podrá detenerse cuando:

- Sea necesario tomar una decisión funcional importante.
- Exista un problema de seguridad.
- Sea necesario modificar la arquitectura.
- Exista un conflicto técnico que no pueda resolverse automáticamente.

## Fases

| Fase | Contenido |
| --- | --- |
| **Fase 1** | Arquitectura. Base de datos. Autenticación. Seguridad. Infraestructura. Sincronización. Proyecto base completamente funcional. |
| **Fase 2** | Implementación completa de todas las funcionalidades. Pantallas. IA. Offline. Notificaciones. Integraciones. |
| **Fase 3** | Optimización. Testing. Auditoría. Escalabilidad. Documentación. Publicación. |

## Calidad

Todo el código deberá cumplir:

- Código limpio.
- Clean Architecture.
- SOLID.
- TypeScript estricto.
- Sin deuda técnica.
- Documentado.
- Probado.
- Optimizado.
- Preparado para producción.

## Seguridad

La seguridad tendrá prioridad sobre la velocidad de desarrollo.

- Nunca almacenar información privada sin cifrar.
- Nunca guardar claves en texto plano.
- Nunca permitir accesos sin autorización.
- Nunca enviar información sensible sin cifrado.

## Privacidad

La empresa nunca podrá leer: diario espiritual, oraciones, memorial,
reflexiones, notas privadas.

Todo deberá cifrarse antes de abandonar el dispositivo.

## Experiencia de usuario

El usuario deberá sentir: paz, esperanza, seguridad, orden, sencillez.

Nunca culpa. Nunca ansiedad. Nunca presión.

## Diseño

Toda la aplicación utilizará un único sistema visual basado en Liquid Glass.
Todas las pantallas deberán mantener coherencia visual. No se permitirá mezclar
estilos.

## Objetivo final

Construir una aplicación que cualquier cristiano pueda utilizar durante años
para fortalecer su relación con Dios, con una calidad comparable a las mejores
aplicaciones del mercado y una privacidad superior a la mayoría de ellas.
